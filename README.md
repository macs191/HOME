# HOME SERVICE

منصة عربية RTL لحجز الخدمات المنزلية، مبنية بـ React وVite وTypeScript، ومرتبطة بمشروع Supabase لـ PostgreSQL/Auth/Storage/Realtime. التسجيل متاح للعميل والفني، وملف الفني يبدأ بحالة `pending` ولا تُرفع الصلاحيات من الواجهة. الحجز يستخدم RPC آمنًا باسم `create_booking_with_consent` يسجل نسخة سياسة الطلب ووقت موافقة العميل. مساحة العميل تقرأ الطلبات الحقيقية وتعرض مسار الدفع النقدي أو التحويل.

## التشغيل المحلي

```bash
npm install
npm run dev
```

يفتح Vite على المنفذ `3000`. للفحص والبناء:

```bash
npm run typecheck
npm run build
```

## متغيرات البيئة

انسخ `.env.example` إلى `.env` وضع قيم Supabase العامة فقط:

```bash
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_ANON_KEY
```

لا تضع `SUPABASE_SERVICE_ROLE_KEY` أو مفاتيح الدفع أو أي سر في Vite أو GitHub. العمليات الحساسة، مثل تغيير الأدوار أو اعتماد الفني أو تأكيد الدفع، يجب تنفيذها عبر Edge Functions أو خادم موثوق.

## إعداد Supabase

1. المشروع المرتبط حاليًا هو `ojivulfurjjsskqzghfb`، وقد تم تجهيز `public` وحسابات Auth وكتالوج HOME SERVICE.
2. **لا تعِد تطبيق** `20261010000000_initial_schema.sql` على قاعدة الإنتاج المرتبطة. لمشروع Supabase جديد، ابدأ من قاعدة اختبار منفصلة وراجع baseline وتسلسل الملفات أولًا؛ سجل الإصدارات الحالي يحتاج تسوية موثقة كما هو مفصل في تقرير المراجعة.
3. فعّل Email Auth أو مزود تسجيل الدخول المطلوب من Authentication.
4. لا تجعل إنشاء دور `admin` متاحًا من الواجهة. امنح أول مدير عبر SQL آمن بعد تسجيل حسابه ومراجعة معرّف المستخدم:

```sql
update public.user_roles
set role = 'admin'
where user_id = 'USER_UUID_FROM_AUTH_USERS';
```

نفّذ هذا الاستعلام من جلسة إدارية موثوقة فقط، وليس من المتصفح.

## الخرائط والموقع

توجد خريطة تفاعلية تبدأ بوضع **القمر الصناعي** عبر Esri World Imagery مع إسناد المصدر، ويمكن تبديلها إلى طبقة طرق OpenStreetMap. البحث يعمل عبر Google Places عندما تضيف `VITE_GOOGLE_MAPS_API_KEY` كمفتاح مقيّد بالنطاق، ويعود تلقائيًا إلى Nominatim/OpenStreetMap مجانًا عند غياب المفتاح. Google Maps ليس خدمة مجانية بلا شروط: يتطلب API key وتفعيل billing؛ لذلك لا يتم تضمين مفتاح افتراضي أو كشف سر في المستودع. يستخدم النموذج `Geolocation API` بعد موافقة المستخدم، ويدعم العنوان اليدوي والنقر/السحب على الخريطة.

## التخزين والإشعارات

أنشئ buckets خاصة للمرفقات، وطبّق سياسات Storage مرتبطة بالمستخدم والطلب. جدول `notifications` خاص بكل مستخدم ومضاف إلى `supabase_realtime`؛ يرسل التطبيق تنبيهًا داخل الواجهة وإشعار نظام عند وجود إذن المتصفح، مع رابط وجهة آمن، وتفعيل صوت اختياري من مركز الإشعارات. تنشأ تنبيهات للإدارة عند طلب جديد أو ملف اعتماد جديد، وللفني والعميل عند إسناد طلب، ويُخطر العميل بتقدم المهمة. لا تجعل وثائق الفنيين عامة.

على Android يمكن تثبيت الموقع كتطبيق PWA من Chrome عبر «إضافة إلى الشاشة الرئيسية»؛ يوجد خيار **تثبيت التطبيق** في القائمة المنسدلة للموقع، ويعرض تعليمات التثبيت اليدوي عند عدم إتاحة مطالبة المتصفح. يلزم أن يكون الموقع على HTTPS. إشعارات النظام الحالية مرتبطة بصفحة مفتوحة وRealtime؛ استقبال Web Push بعد إغلاق التطبيق يتطلب مفاتيح VAPID وخدمة إرسال خلفية واشتراك المتصفح، وهذا التكامل غير مُعد.

## Vercel

1. المستودع المرتبط: `https://github.com/macs191/HOME`، والفرع `main`.
2. اختر إطار Vite، وأمر البناء `npm run build` ومجلد الناتج `dist`.
3. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` من Project Settings، دون أي Service Role key.
4. نفّذ Deploy ثم اختبر `/`, `/services`, `/book`, `/customer`, `/provider`, `/admin`.
5. بعد نشر الفرع، اختبر مسارات SPA (`/customer/notifications`, `/provider/notifications`, `/admin/notifications`) من متصفح هاتف؛ لا تجرّب عمليات الحساب أو الدفع على بيانات حقيقية بلا جلسة/بيانات اختبار مخصصة.

## حالة الدفع

الواجهة الحالية تعرض الدفع **نقدًا أو بالتحويل البنكي** بعد اعتماد الفاتورة. توجد ملفات مصدر Edge Functions تخص Stripe، لكن من المستودع وحده لا يمكن إثبات نشرها أو إعداد الأسرار والـWebhook، ولا يوجد تأكيد أن Checkout متصل بواجهة العميل حاليًا. لا تعتبر Stripe مفعّلًا حتى يُختبر مسار Checkout والـWebhook في بيئة اختبار مخصصة. لا تضع مفاتيح Stripe أو service-role في Vite أو GitHub.

## صفحات المشروع

- `/` الصفحة الرئيسية والبحث.
- `/services` كتالوج الخدمات والتصفية.
- `/book` حجز متعدد الخطوات مع GPS أو اختيار يدوي.
- `/customer` مساحة العميل، وتتضمن الطلبات والإشعارات.
- `/provider` مساحة الفني، وتتضمن الطلبات والتخصصات والاعتماد والأرباح والإشعارات.
- `/admin` لوحة الإدارة، وتتضمن الحسابات والتشغيل والإشعارات.
- `/login`, `/customer/login`, `/provider/login` مسارات دخول الأدوار عبر Supabase Auth.

## الهوية الملكية وتشغيل الفنيين
- زر طلب الخدمة يفتح حوار حساب قبل إدخال العنوان، مع Google OAuth عند تفعيل Google provider في Supabase Auth.
- بعد أول دخول للفني، بما في ذلك Google، تظهر نافذة مركزية لإكمال الاسم والجوال والمدينة والخبرة والتخصصات ورفع وجهي الهوية والسيرة الذاتية. تتحقق قاعدة البيانات من وصول الملفات فعليًا إلى الـ buckets الخاصة قبل تثبيت طلب الاعتماد؛ روابط الإدارة مؤقتة وآمنة ولا تظهر للعملاء.
- كان سبب رسالة «تعذر حفظ الملف» غياب جدول `public.audit_logs` الذي تستدعيه دالة حفظ الاعتماد؛ فكان فشل سجل التدقيق يلغي معاملة الحفظ كاملة. أُضيف الجدول بسياسات قراءة للإدارة فقط في migration `20261012171113_fix_provider_submission_audit_and_name.sql`.
- لوحة الإدارة تحتوي على إسناد طلب وقيود أجر/خصم/تسوية عبر RPC. طبّق migrations المرقمة في `supabase/migrations/` بالترتيب على قاعدة Supabase قبل التشغيل.
- مشروع Supabase المرتبط: `ojivulfurjjsskqzghfb`. مستندات الهوية في bucket خاص بحدّ 5MB وصيغ JPG/PNG، والسيرة في bucket خاص بحدّ 10MB وصيغ PDF/DOC/DOCX. الجلسات محفوظة وتجدد تلقائيًا، ويعيد مسار طلب العميل الخدمة المختارة بعد تسجيل الدخول. تتطلب مدفوعات Stripe ضبط أسرار Edge Functions، كما تتطلب إشعارات Web Push بعد إغلاق التطبيق إعداد VAPID وخدمة إرسال خلفية.
- تنفّذ لوحة الحسابات تعديلات ملفات العميل/الفني، مراجعة وثائق الاعتماد، وتفعيل/إيقاف الحساب. الحذف الدائم مسموح للحسابات التي لا ترتبط بطلبات أو قيود مالية؛ الحسابات ذات السجل تُوقَف بدلًا من حذف تاريخ المعاملات.
